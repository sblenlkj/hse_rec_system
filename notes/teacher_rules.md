# Правила и требования преподавателя

## Соревнование

**HSE RecSys Challenge 2026**

- Страница данных: https://www.kaggle.com/competitions/hse-rec-sys-challenge-2026/data
- Invite-ссылка: https://www.kaggle.com/t/9278d7f880b34ac7ad249146fd168771
- Дедлайн: **31 октября, суббота, 08:00 по Москве**
- Команда: не более **7 человек**
- Лимит: **10 сабмитов в день** (может быть увеличен преподавателем)
- Формат ответа: **10 фильмов для каждого пользователя**
- Основная метрика: **Recall@10**

## Файлы соревнования

- `events.csv` — взаимодействия пользователей / история оценок;
- `user_features.csv` — признаки пользователей;
- `item_features.csv` — признаки фильмов;
- `submission_sample.csv` — пример сабмита.

Формат сабмита определяется `submission_sample.csv`.

## Оценивание

Оценка зависит от лучшего сабмита команды.

Необходимо превзойти соответствующие baseline:
- `baseline_5`;
- `baseline_4`;
- `baseline_3`.

Точные значения baseline нужно брать со страницы соревнования / leaderboard и не дублировать вручную без необходимости.

## Обязательные условия зачёта

1. Предоставить **воспроизводимое решение**.
2. Git-репозиторий должен содержать код лучшего сабмита.
3. Метрика лучшего сабмита должна воспроизводиться при повторном запуске.
4. Решение должно запускаться:
   - одной командой, **или**
   - одним полным запуском одного ноутбука.
5. В репозитории должен быть документ с полноценным описанием:
   - всех проверенных гипотез;
   - всех существенных сабмитов;
   - пути рассуждений команды;
   - полученных метрик;
   - выводов после каждого этапа.
6. При вопросах по решению команда может быть приглашена на устный зачёт полным составом; каждый участник должен уметь объяснить решение.

## Что преподаватель отдельно подчеркнул

### 1. Бейзлайны лёгкие

Не стоит откладывать первый рабочий сабмит. Нужно как можно раньше:
- собрать простой baseline;
- проверить pipeline;
- понять связь local validation и Kaggle.

### 2. Transformer baseline стоит попробовать заранее

Преподаватель предупредил, что baseline может легко пробиваться моделями:
- GPT4Rec;
- SASRec;
- BERT4Rec.

Возможен сценарий, когда это окажется почти `fit -> predict`.

Поэтому transformer-based baseline нужно получить рано, но не строить весь проект только вокруг него.

### 3. Может появиться требование решить задачу без трансформера

Если трансформеры окажутся слишком простым способом пройти baseline, преподаватель может потребовать отдельное non-transformer решение.

Поэтому параллельно нужно развивать классическую ветку:
- similarity;
- KNN;
- ALS / MF;
- candidate generation;
- feature engineering;
- boosting / reranking;
- ensembles.

### 4. Рекомендуемая библиотека

Для SASRec / BERT4Rec преподаватель рекомендует **RePlay**:

https://github.com/sb-ai-lab/RePlay/blob/main/examples/09_sasrec_example.ipynb

## Критически важное правило нашей локальной валидации

Преподаватель отдельно предупреждал о риске заглянуть в будущее. После EDA выяснилось, что предоставленный `timestamp` не является общей календарной датой, поэтому буквально провести один абсолютный cutoff для всех пользователей нельзя.

Наша реализация принципа «не смотреть в будущее»:

- сортируем историю каждого пользователя по timestamp;
- держим последние 10% как validation;
- все признаки, статистики, embeddings и модели строятся **только по train**;
- validation используется только как ground truth;
- split фиксируется и не меняется между экспериментами без отдельной пометки.

Отдельно можем исследовать masked holdout как имитацию Kaggle hidden set, но не смешиваем его результаты с основной chronological validation.
